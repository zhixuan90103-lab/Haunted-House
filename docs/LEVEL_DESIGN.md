## 1. 检索结论：好谜题的共同标准

综合 GDC 谜题讲座、行业文章、Zachtronics/手工谜题社区、ThinkFun 类光路题等，反复出现的标准是：

| 标准 | 含义 |
|------|------|
| **可解且公平** | 玩家具备全部必要信息与规则；不靠隐藏说明书外知识 |
| **目标清晰** | 一眼知道「要达成什么」（本项目：全员完全显示 → 拍照） |
| **有思考不只试错** | 理想是可推理；允许试，但不应只能盲试 |
| **教过再用** | 新机制先单独教，再组合 |
| **有「顿悟」** | 解出来时觉得聪明，而不是被恶心 |
| **为玩家好玩，不为设计师炫技** | 常见提醒：谜题是给玩家爽的 |

**内部逻辑 vs 设计师逻辑**（常见分野）：

- **内部逻辑（推荐本项目）**：解法来自已公布规则（直线光、镜 90°、漫射 8 格…）。  
- **设计师逻辑（慎用）**：玩家无法从规则推出，只能猜设计师心思。

本项目光学规则固定 → 关卡应走 **内部逻辑**。

## 2. 两种主流「做题」方法

行业里两种都常用，可混用。

### 2.1 自解法倒推（Top-down / Work backwards）

```
先定一个「有趣的终态 / 标准解」
  → 摆好手电朝向、镜、漫射、墙、鬼位
  → 验证：全员完全显示可拍照
  → 再往回删信息、加障碍、收紧托盘
  → 保证仍可解，且尽量「有想法」
```

**优点**：天然可解；适合固定谜题、光路题。  
**风险**：可能变成「只有我知道的唯一路径」；要自测有没有第二条合法解（你们允许多组合，不必强唯一）。

社区共识（Reddit / 多篇设计文）：*Start with the solved state and work backwards.*

### 2.2 正向演绎链（Forward design）

```
从空盘开始
  → 想「玩家第一步会推什么」
  → 放约束，使下一步也被迫/自然成立
  → 串成一条推理链
```

**优点**：关卡更像「引导思考过程」。  
**风险**：中途容易做成无解或过碎。

### 2.3 本项目建议默认流程

```
① 选「这一关教/考什么」（一个核心想法）
② 用倒推搭出一条标准解光路
③ 用场景墙 + 托盘限制 去掉无聊解
④ 自测：新手会不会卡死 / 会不会 3 秒秒杀
⑤ 写清关卡卡（见 §7）
⑥ 至少一人盲测
```

## 3. 光路类谜题可借鉴的「关卡语法」

### 3.1 ThinkFun Laser Maze 型（实体题卡）

公开说明书与产品结构的核心是 **Challenge Card**：

| 卡上信息 | 作用 |
|----------|------|
| 部分棋子**固定位置与朝向**（必须按图摆） | 降低自由度，聚焦思路 |
| 部分棋子由玩家自由摆 | 真正的解空间 |
| 目标：激光点亮指定目标 | 与「照亮鬼格」同构 |
| 难度分档 Beginner → Expert | 曲线可见 |

**可直接借鉴到本项目的卡结构**见 §7。

玩法循环也同构：

```
布置 → 开光验证 → 不对再改 → 全目标亮 = 成功
```

我们多一步：**全员完全显示 → 拍照**（验证 UX 可做成「自动检光 + 进相机」）。

### 3.2 数字激光/反光手游的常见做法

（Laser Puzzle 类：转镜、点亮全部灯泡）

| 做法 | 说明 |
|------|------|
| 早期只转、不挪 | 教反射 |
| 中期加墙/挡块 | 直线被废，必须折 |
| 后期加特殊件 | 传送、分束等；我们对应漫射/多灯 |
| 无时限、可重试 | 符合休闲 |

### 3.3 光路关卡的「原子技巧」（出题零件）

设计时可显式选用 1～2 个，避免一关堆满：

| 原子 | 玩家要学会的事 | 本项目映射 |
|------|----------------|------------|
| 直射 | 光走直线 | 光源、无镜照一鬼 |
| 单次反射 | 镜 90° | 基础镜拐一次 |
| 半透分束 | 一进两出（反+透） | **半透半反镜**（确定件） |
| 多次反射 | 折线串联 | 多镜/长路径 |
| 挡直逼折 | 墙废掉直线 | 场景墙 |
| 多目标分流 | 一条路不够 | 多鬼分散 |
| 扩面 | 邻域覆盖 | **漫射灯** |
| 多源并集 | 两灯分工 | 多光源 |
| 占格冲突 | 一格一物 | 鬼占格、道具互斥 |
| 反面无效 | 镜朝向要对 | 镜/半透反面当墙 |
| 资源不足 | 不能滥摆 | 托盘件数 |

确定道具与备选完整列表见 `PRODUCT.md` §9.1。

**一关最好主打一个原子**；组合关再叠 2～3 个。

## 4. 教学与难度曲线（通用 + 本项目）

### 4.1 经典「教法」原则

来自多源（GDC、手游进度文、谜题设计指南）：

1. **先给甜头**：第 1 关必过、建立「光→亮→过关」心智。  
2. **一次只教一个新东西**：新道具单独一关「展示关」。  
3. **再练再考**：展示后 1～2 关巩固，再进组合。  
4. **锯齿难度**：连续加压后插一关稍易，恢复信心。  
5. **后期做变奏**：同一规则换空间形状，而非只加件数。

### 4.2 建议的机制解锁序（本项目）

```
批次 A  光直线 + 一鬼 + 一光源（可无镜）
批次 B  基础镜 90° + 单鬼
批次 C  墙挡直线
批次 D  两鬼 + 必须布局（单灯直射不够）
批次 E  半透半反镜（一源两路）
批次 F  漫射灯
批次 G  多光源并集
批次 H  镜/半透反面与朝向 + 紧托盘
批次 I  综合（仍控制原子数量；备选道具仅在 teaches 标明后使用）
```

探查（隐藏→透明→显示）可：

- 与 A 同时存在（拖光就会碰到）；或  
- 前几关弱化（鬼已透明），中期再强调「要扫」。

拍照：从第一关就有，建立「全亮才合影」；避免后期才突然加规则。

### 4.3 难度旋钮（对应 PRODUCT 关卡参数）

| 旋钮 | 调难 | 调易 |
|------|------|------|
| 鬼数量/分散度 | 多且对角线分散 | 少且共线 |
| 墙 | 封死直线 | 空旷 |
| 托盘件数 | 少、紧 | 多、冗余件（慎：增噪声） |
| 镜数 | 必须多折 | 零或一 |
| 漫射 | 必须靠 8 邻 | 不用 |
| 手电数 | 必须双源 | 单源 |
| 固定件 | 盘上预置错误诱惑位 | 无预置 |

**注意**：冗余道具会增加「噪声」与误导，新手关慎用；专家关可作假线索。

## 5. 推荐制作工序（实操清单）

### 步骤 1：写「关卡意图」一句话

例：

- 「教镜直角拐弯」  
- 「单灯照不到两只对角鬼，必须折或漫射」  
- 「托盘只有一镜，墙封死直射」

没有意图的关容易变成随机堆件。

### 步骤 2：搭标准解

1. 在 5×5（或本关尺寸）放墙/场景。  
2. 放鬼位。  
3. 从托盘概念上摆手电、镜、漫射至「全员完全显示」。  
4. 记录朝向与坐标（内部标准解）。  
5. 用规则手算或日后编辑器模拟光路。

### 步骤 3：加压 / 整形

- 拿走「多余直射」可能：加墙。  
- 收托盘：只留解需要的件（或留 1 个干扰件，后期再用）。  
- 检查：是否存在「乱放也过」的平凡解；有则加压。  
- 检查：是否只有超级冷门解；有则加引导或改盘。

### 步骤 4：可解性与公平性

| 检查 | 问句 |
|------|------|
| 可解 | 标准解在现行 `PRODUCT` 规则下成立吗？ |
| 信息 | 玩家是否已学过本关用到的规则？ |
| 反馈 | 光预览/亮格是否足够判断对错？（实现向） |
| 重开 | 重开成本是否可接受？（已定回最初） |
| 误导 | 假路径是否「可证伪」而不是恶心？ |

### 步骤 5：盲测

- 作者以外的人玩；不讲解。  
- 记录：卡点、误触、是否理解拍照。  
- 超时过久 → 降噪或加教学关。  
- 秒过 → 加压或并入前一关。

### 步骤 6：归档题卡

写入 §7 模板，进关卡表。

## 6. 常见坏关（避坑）

| 坏模式 | 表现 | 处理 |
|--------|------|------|
| 无解 | 规则下达不到全亮 | 倒推重做；自动化校验（以后） |
| 平凡解 | 不思考直线全中 | 分散鬼 / 加墙 |
| 像素折磨 | 斜向/精度 | 标准解坚持四向 |
| 说明书关 | 必须外部知识 | 只考已教规则 |
| 一次考太多 | 新镜+新漫射+双灯+满墙 | 拆关 |
| 噪声托盘 | 5 件只有 2 件有用且无提示 | 新手关少冗余 |
| 设计师独解 | 唯一解靠冷门 | 允许多组合或改盘 |
| 炫技光路 | 折 10 次无新概念 | 缩短路径，加概念 |

名言向提醒（GDC 谜题向观众评论常引）：  
**Puzzles are fun for the player, not the designer.**

## 7. 关卡卡模板（本项目）

每关建议固定字段（可复制填空）：

```yaml
id: level_001
title: 可选展示名
intent: 一句话意图（教/考什么）
board:
  size: [5, 5]          # 宽, 高
  walls: []             # 挡光格列表 [x,y] 或矩形
  # furniture: []       # 其他场景件（以后扩展）
ghosts:
  - { x: 0, y: 0 }
  # ...
tray:                   # 玩家可拖入的道具
  - { type: flashlight, count: 1 }
  - { type: mirror, count: 1 }
  - { type: diffuser, count: 0 }
# 可选：开局已在盘上且锁定的场景镜等
scene_props: []
# 内部用，不对玩家显示
reference_solution:
  notes: "标准解说明"
  placements:
    - { type: flashlight, x: 0, y: 0, facing: E }
    - { type: mirror, x: 1, y: 0, facing: 0 }
difficulty: 1           # 1–5 或 tutorial/normal/hard
tags: [intro, mirror]   # 原子标签
teaches: [beam_straight] # 本关新教内容
requires: []            # 依赖已教内容
```

**Laser Maze 式「强制预摆」**（可选进阶）：

```yaml
locked_placements:
  - { type: mirror, x: 2, y: 2, facing: 1, locked: true }
```

用于：减少自由度、突出某一反射。

## 8. 本项目特殊维度（出题时别忘）

相对纯激光灯泡题，多出来的设计轴：

| 维度 | 出题含义 |
|------|----------|
| 鬼占格 | 该格不能放道具 → 路径要绕开站位 |
| 状态机 | 可设计「先扫再布」节奏；或中期关强调探查 |
| 拍照门 | 胜利是**同时全显示**，不是「曾经照到过」 |
| 托盘拖放 | 与「盘上只转镜」不同，要考虑放哪一格 |
| 一格一物 | 光路与占位强耦合，小盘更紧 |

出题检查多问一句：

> 若所有鬼改成「不占格的灯泡」，这关还成立吗？  
> 若成立，是否浪费了「鬼占格」这根轴？

## 9. 工具与流程建议（制作效率）

| 手段 | 用途 |
|------|------|
| 纸笔 / 表格 5×5 | 最快倒推 |
| 关卡 YAML/JSON | 与引擎共用 |

## 11. 出题最短检查表（打印用）

```
[ ] 一句话意图清楚
[ ] 只主考 1 个新原子（或明确综合关）
[ ] 标准解在 PRODUCT 规则下可复现
[ ] 托盘件数与场景已写进题卡
[ ] 无「必须未教规则」
[ ] 非 3 秒平凡直射（除非教学关）
[ ] 非无解
[ ] 鬼占格/一格一物已考虑
[ ] 全员同时显示才能过（非曾经照到）
[ ] 盲测过或计划盲测
[ ] tags / difficulty 已填
```
